# АРУ перед VAD в псевдостриминге

Дата: 2026-11-06. Ветка `feat/speech-agc` (поверх `feat/speech-bench-realtime`).
Стенд и метрики — как в [`bench-golden-baseline.md`](bench-golden-baseline.md):
эмулятор API 36 x86_64, 4 ядра, `--pace 1`, один прогон на конфигурацию.

## Проблема

Реальная запись разговора двух человек (31 с, голосовое сообщение; в
репозиторий не входит): один говорит рядом с микрофоном (−23 dBFS), второй —
дальше (−33…−37 dBFS при фоне −47). Silero VAD не распознал как речь **~9 с
разборчивой речи дальнего собеседника**: в журнале на этих участках нет ни
`SpeechStarted`, ни VAD-чанка. Порог VAD 0,35 и 0,25 не помог; batch (pyannote)
эту речь находил. После выравнивания громкости в ffmpeg та же речь находилась —
значит, нужна АРУ перед VAD.

## Что сделано

`AutomaticGainControl` (`speech/audio`), `SpeechConfig.agc` (по умолчанию включена):

- только прошлый сигнал, без задержки и без буфера: длина выхода = длина входа;
- кадры по 20 мс; уровень фона — минимум сглаженного уровня за 5 с, цифровая
  тишина (ниже −70 dBFS) в оценку не входит;
- кадр — речь, если на 6 дБ громче фона; только на таких кадрах растёт усиление
  (к −20 dBFS, потолок +24 дБ, громкую речь не приглушает);
- в паузах усиление возвращается к 0 дБ;
- **выровненный сигнал видит только VAD**: ASR и embedding получают исходный
  отрезок из кольцевого буфера на 90 с.

## Три итерации

Первая версия выглядела хорошо на проблемной записи, но на остальных сломала
другое — каждую правку нашли по журналу и симуляции:

| Версия | Что пошло не так | Исправление |
|---|---|---|
| v1: АРУ на весь сигнал | 3 голоса → 1, кафе 2 → 1, длинный файл 8 → 3 спикеров: меняющееся усиление и поднятый фон портили embedding | ASR и embedding — по исходному сигналу |
| v2 | живой монолог слипся в один чанк на 25 с (первый текст на 30-й секунде) | — |
| | причина: трекер фона «быстро вниз, медленно вверх» залип на −97 dBFS после нулей в начале файла, и паузы считались речью; усиление в паузе росло до +12 дБ | фон — минимум за окно 5 с без цифровой тишины; в паузах усиление → 0 дБ |
| v3 | — | итоговая |

## Результат v3

### Реальные записи (не в репозитории)

| | Без АРУ | С АРУ |
|---|---|---|
| Разговор, дальний собеседник: потеряно речи | ~9 с | 0 |
| Там же: спикеров найдено (их 2) | 1 | 2 |
| Громкий монолог: нарезка и текст | — | без изменений |

### Золотой набор (8 файлов, реальное время)

| | Без АРУ | С АРУ |
|---|---:|---:|
| WER | 16,0 % | 16,6 % |
| spkErr (медиана) | 11,5 % | 11,9 % |
| Число спикеров угадано | 7 из 8 | **8 из 8** |
| Группа из 3 голосов: spkErr | 82,4 % | **30,8 %** |
| Задержка: медиана / p90 / максимум | 0,76 / 2,96 / 11,22 с | 0,85 / **1,71** / 10,49 с |
| Отставание от реального времени | 0 | 0 |
| `golden_long` (6 мин): WER / p90 | 17,4 % / 6,43 с | **16,8 % / 2,77 с** |

Рост WER на 0,6 п. п. почти весь из `syn26_simult2` (одновременная речь,
28,9 → 33,7 %): вставки второго голоса есть в обоих прогонах, разница — другой
порядок перекрывающихся фраз и одно слово, обрезанное на границе чанка. На
остальных файлах WER тот же или ниже.

Синтетика тихая (−39…−47 dBFS), поэтому АРУ её тоже поднимает и меняет границы
VAD — отсюда изменения и в лучшую (задержка, число спикеров), и в худшую сторону.

## Ограничения

- Одна живая запись с дальним собеседником — нужно больше живых разговоров.
- АРУ проверена на файлах; у живого микрофона Android может быть своя АРУ
  (`VOICE_RECOGNITION`, `AutomaticGainControl`) — их взаимодействие не
  проверялось.
- Один прогон на конфигурацию.

## Как воспроизвести

```bash
bash speech/eval/run_golden.sh bench-results/agc/on  --mode streaming --pace 1 --runs 1 --agc on
bash speech/eval/run_golden.sh bench-results/agc/off --no-build --mode streaming --pace 1 --runs 1 --agc off
```

Логи АРУ: `adb shell setprop log.tag.Speech DEBUG` — у каждого VAD-чанка
`gain=…dB`, в итоге сессии `agcMax=…dB`.

Сырые JSON прогонов в git не хранятся (локально — `bench-results/`): повторить
можно бенчмарком `speech/scripts/benchmark.sh`. Базовая линия без АРУ —
серии A и E в [`bench-golden-baseline.md`](bench-golden-baseline.md).
