# Точность транскрибации: где пайплайн теряет слова

Дата: 2026-11-07. Ветка `feat/speech-asr-edges` (поверх `feat/speech-eres2net`).
Расшифровка файлов через `SherpaVadTranscriber` (`--mode vad`), эмулятор API 36
x86_64, один прогон на файл. Разбор — на хосте той же моделью GigaAM
(sherpa-onnx Python), проверка — на эмуляторе.

## Итог на устройстве

| Набор | WER: было → стало | spkErr | спикеров верно | начало реплики, медиана | RTF |
|---|---|---|---|---|---|
| dialogs (живые голоса, 12) | 7,4 → **3,9 %** | 5,4 → 4,5 % | 11/12 | 0,35 → 0,19 с | 0,21 → 0,17 |
| dialogs2 (проверка, 12) | 6,7 → **3,7 %** | 4,5 → 2,9 % | 12/12 | 0,32 → 0,13 с | 0,22 → 0,16 |
| синтетика (26) | 16,5 → 16,2 % | 13,5 → 12,4 % | 15 → 17 | 0,93 → 0,91 с | 0,12 → 0,09 |
| val2 (19) | 19,8 → 19,5 % | 13,2 → 12,6 % | 12 → 11 | 1,02 → 1,02 с | — → 0,10 |

«Было» — ERes2Net с прежней нарезкой ([`bench-eres2net.md`](bench-eres2net.md)).
RTF «было» на синтетике и val2 завышен: тот прогон шёл параллельно с
расчётами на хосте. Для сравнения, CAM++ с прежней нарезкой: RTF 0,14 на
диалогах, 0,09 на синтетике. Пиковый PSS бенчмарка вырос с ~620 до ~760 МБ:
ASR теперь видит чанк до 25 с целиком.

WER считается с новой нормализацией `score_wer.py`: латинские буквы-двойники
внутри русских слов приводятся к кириллице. В эталоне одного диалога
скороговорка набрана с латинской «p» («зpения»), и без этого правильный
ответ модели считался ошибкой (было 8,5 % вместо 7,4 % на dialogs).

## Сколько теряет пайплайн

dialogs, 4 937 слов эталона. «Идеальная нарезка» — каждая реплика эталона
вырезана с запасом 0,2 с и распознана отдельно.

| | ошибок | WER |
|---|---:|---:|
| идеальная нарезка (только модель) | 231 | 4,7 % |
| прежний пайплайн на устройстве | 365 | 7,4 % |

Из 195 ошибок, которых нет при идеальной нарезке, 102 стоят у края куска.
Два типа:

- **слово разрезано пополам**: «[+полу] | [получилось→сучилось]», «[+шлу] школу»;
- **конец куска потерян или испорчен**: «[-и] [-утрате] |», «[-в] | разных городах».

Нашлись две причины.

### 1. Слепой разрез длинного сегмента VAD

Silero VAD в sherpa-onnx не соблюдает `maxSpeechDuration`: в диалогах, где паузы
между репликами короче 450 мс, сегменты доходят до 105 с (медиана 27 с).
`splitLongVadSegment` резал их ровно каждые 25 с — посреди слова.

Хост, только VAD + ASR кусков, без поиска смены говорящего:

| нарезка длинных сегментов | WER |
|---|---:|
| не резать (до 105 с) | 5,00 % |
| ровно каждые 25 с (как было) | 4,96 %, вставок вдвое больше |
| **в самом тихом окне 100 мс среди последних 10 с перед лимитом 25 с** | **4,05 %** |
| то же, лимит 20 / 15 / 10 с | 4,19 / 4,48 / 4,96 % |

Короткие куски GigaAM распознаёт хуже: лимит 25 с оставлен.

### 2. Разрез звука по смене говорящего

Каждая точка смены говорящего резала звук, и куски распознавались по
отдельности. Точек слишком много: ERes2Net с порогом 0,65 ставит 416 точек на
12 диалогов, из них лишь 179 рядом с настоящей сменой. Каждый ложный разрез
ломает слово.

| порог смены говорящего | точек | верных | WER |
|---:|---:|---:|---:|
| 0,30 | 39 | 36 | 4,17 % |
| 0,40 | 79 | 63 | 4,33 % |
| 0,50 | 175 | 127 | 4,66 % |
| 0,65 (по умолчанию) | 416 | 179 | 6,68 % |
| без разрезов звука | — | — | **4,05 %** |

Понизить порог нельзя: из 262 смен говорящего 211 приходятся на паузу короче
450 мс, то есть внутрь VAD-чанка. При 0,30 найдено бы 36 из них — диаризация
развалилась бы.

## Что сделано

1. **Длинный сегмент VAD режется в тишине** (`splitLongVadSegment`): самое тихое
   окно 100 мс (шаг 10 мс) среди последних 10 с перед лимитом.
2. **ASR — по всему чанку, разрезы делят только слова.** Точки смены
   говорящего и разрез по тихому кадру остались прежними; слово относится к
   куску, в котором начинается; embedding спикера — по участку со словами куска.
3. **Страховка от наложения голосов.** На одновременной речи GigaAM по целому
   чанку иногда выдаёт обрывки (hold44: WER 33 → 62 %, v19: 31 → 48 %), а
   короткие куски с одним голосом распознаёт нормально. Если целый чанк дал
   меньше 2 слов/с и есть разрезы, куски распознаются ещё раз отдельно; их
   текст берётся, если слов в них больше на 10 % + 1.

Хост, 12 диалогов и 45 синтетических файлов, лимит 25 с с разрезом в тишине:

| текст чанка | живые | синтетика | второй проход ASR |
|---|---:|---:|---:|
| только куски по смене говорящего | 6,68 % | 18,57 % | — |
| целый чанк | 4,05 % | 20,25 % | — |
| целый чанк, куски — если в них слов больше на 10 % + 1 | 4,05 % | 18,40 % | 75 % звука |
| **то же, только если в целом чанке < 2 слов/с** | **4,05 %** | **18,40 %** | **29 % звука** |

Проверено и не взято: добавить 300 мс тишины в конец куска — без эффекта
(5,06 против 5,00 %); расширить кусок на ±250 мс соседнего звука — 4,82 против
5,00 %, мало для лишней сложности.

## Что осталось

Оставшиеся ~4 % на живых голосах — ошибки самой модели: при идеальной
нарезке 4,7 %, из них формы слов (окончания) — 64 из 231, прочие замены — 78,
короткие вставки и пропуски — 44, числа — 9. Выигрыш дальше — только от
другой модели ASR (GigaAM RNNT, fp16) — не проверялось.

## Что изменилось в коде

- `VadChunkSplitter.splitLongVadSegment` — разрез в самом тихом окне.
- `StreamingChunkProcessor.process` — ASR всего чанка, слова по кускам,
  перепроверка кусков на разреженном выходе (`COLLAPSE_*`).
- `speech/eval/score_wer.py` — латинские двойники в русских словах.

Скрипты разбора (хост, sherpa-onnx Python) — не в репозитории: идеальная
нарезка, копия VAD-пайплайна с поиском смены говорящего и подбор правила.

Сырые JSON прогонов в git не хранятся (локально — `bench-results/`): повторить
можно бенчмарком `speech/scripts/benchmark.sh`.
