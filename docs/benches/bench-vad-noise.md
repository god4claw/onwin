# VAD в шуме: порог Silero, АРУ, TEN VAD

Дата: 2026-11-06. Ветка `feat/speech-vad-noise`. Расшифровка файлов через
`SherpaVadTranscriber` (`--mode vad`), эмулятор API 36 x86_64, один прогон на
файл. Наборы: golden (8) + отложенная выборка (18) — 26 файлов; плюс **val2** —
19 новых разговоров из следующего шарда датасета, на которых ничего не
подбиралось (`make_golden.py --val2`).

## Проблема

В шуме Silero VAD с порогом 0,5 терял речь целиком: `hold39_white2` (белый шум,
SNR 16 дБ) — 13 удалённых слов из 40, реплика «как долго готовить индейку…» не
попала в расшифровку вовсе.

## Эксперименты (26 файлов)

| Конфигурация | WER | удалено слов | spkErr | спикеров верно | RTF |
|---|---:|---:|---:|---:|---:|
| Silero 0,5, АРУ (было) | 16,3 % | 65 | 10,6 % | 21/26 | 0,068 |
| Silero 0,5, **без АРУ** | 17,9 % | 99 | 11,0 % | 20/26 | 0,070 |
| Silero 0,4 | 16,0 % | 62 | 9,1 % | 19/25* | 0,080 |
| **Silero 0,35** | **15,9 %** | 61 | **9,1 %** | 19/26 | 0,073 |
| Silero 0,3 | 15,4 % | 56 | 9,1 % | 18/26 | 0,082 |
| TEN VAD 0,5 | 24,1 % | 195 | 9,6 % | 20/26 | 0,062 |
| TEN VAD 0,35 | 16,2 % | 67 | 11,8 % | 22/26 | 0,093 |

\* один прогон упал во время параллельной сборки Gradle; повтор того же файла
дважды прошёл — сбой стенда, не пайплайна.

- **АРУ нужна и на синтетике**: без неё удалений в полтора раза больше.
- **Ниже порог — меньше потерь, но при 0,3 VAD начинает принимать шум за речь**:
  из таких кусков вырастают лишние спикеры (4 файла), растёт spkErr на почти
  безошибочных файлах.
- **TEN VAD не лучше Silero**: при 0,5 массово теряет речь в шуме, при 0,35 —
  вровень по WER, хуже по атрибуции и медленнее. Плюс неясная лицензия (поверх
  Apache 2.0 у TEN есть доп. условия). Поддержку в код не добавляли.

## Подгонку поймала новая выборка

На 26 файлах лучшим выглядело сочетание «VAD 0,35 + перекластеризация с порогом
0,65 и минимальным кластером 4 с» (spkErr 6,7 %, спикеров верно 22/26). На val2,
которую подбор не видел, оно оказалось **хуже** текущей перекластеризации:

| val2 (19 файлов) | WER | удалено | spkErr | спикеров верно |
|---|---:|---:|---:|---:|
| VAD 0,5, перекластеризация 0,60 (было) | 20,8 % | 46 | 10,0 % | 14/19 |
| **VAD 0,35, перекластеризация 0,60** | **20,4 %** | **32** | **9,6 %** | **15/19** |
| VAD 0,35, перекластеризация 0,65 / 4 с | 20,4 % | 32 | 11,6 % | 12/19 |

Параметры перекластеризации не меняем. Меняем только порог VAD.

## Изменение

`VadConfig.threshold`: 0,5 → **0,35** (по умолчанию для streaming и
`SherpaVadTranscriber`).

| | было | стало |
|---|---:|---:|
| WER, 26 / val2 | 16,3 / 20,8 % | **15,9 / 20,4 %** |
| удалено слов, 26 / val2 | 65 / 46 | **61 / 32** |
| spkErr, 26 / val2 | 10,6 / 10,0 % | **9,1 / 9,6 %** |
| спикеров верно, 26 / val2 | 21 / 14 | 19 / 15 |
| RTF | 0,068–0,071 | 0,073–0,081 |

Живые записи: монолог — без изменений; разговор с дальним собеседником —
атрибуция 18,0 → 17,0 %.

Не проверено: задержка живого streaming с новым порогом (на баллы не влияет —
жюри проверяет файлы).

## Как воспроизвести

```bash
python speech/eval/make_golden.py speech/eval/synthetic/train-00001-of-00030.parquet \
    speech/eval/val2 --val2
GOLDEN_DIR=speech/eval/val2 bash speech/eval/run_golden.sh bench-results/val2 --mode vad --runs 1
```

Сырые JSON прогонов в git не хранятся (локально — `bench-results/`): повторить
можно бенчмарком `../../speech/scripts/benchmark.sh`.
