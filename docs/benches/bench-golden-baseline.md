# Псевдостриминг: базовые замеры на золотом наборе

Дата: 2026-11-06. Ветка `feat/speech-bench-realtime` — стенд из
[`../../speech/BENCHMARK.md`](../../speech/BENCHMARK.md) (`--pace`, задержки, WER, логи).
Код псевдостриминга не менялся: это замер того, что есть в `main`.

## Стенд

- Эмулятор `Speech_API36`: Google APIs `sdk_gphone64_x86_64`, Android 16 (API 36),
  4 ядра, 3,8 ГБ RAM, KVM.
- Хост: AMD Ryzen 5 4500U, 6 ядер без SMT.
- `threads=4`, `chunkMs=100`, остальные параметры — по умолчанию `SpeechConfig`.
- **Один прогон на конфигурацию.** Разброс между прогонами не измерялся; разницу
  в доли секунды по задержке и в 1–2 п. п. по WER считать шумом.

С цифрами из README и [`bench-refactor-v2.md`](bench-refactor-v2.md) напрямую не
сравнивать: там другой хост (Ryzen 7 4800H) и 6 ядер эмулятора.

## Набор

8 синтетических разговоров из `ivkond/synthetic-speech-diarization-ru` (MIT),
всего 366 с речи, плюс `golden_long` — они же подряд, 377 с. Состав и причины
выбора — в [`../../speech/eval/make_golden.py`](../../speech/eval/make_golden.py):
диалог, интервью, одновременная речь, белый шум 13 дБ, кафе 10 дБ, группы на 3
и 4 голоса, монолог.

Как читать метрики — [`../../speech/eval/README.md`](../../speech/eval/README.md#golden-set-streaming).
Коротко: **DER на синтетике завышен** (эталонные реплики идут встык и покрывают
паузы), поэтому атрибуцию спикеров смотрим по **spkErr**; в WER часть ошибок —
«десять» в эталоне против «10» у GigaAM.

## Выводы

1. **Скорость с запасом.** Отставание 0 во всех сериях, RTF 0,073 при подаче без
   пауз. Даже если телефон в 5–10 раз медленнее эмулятора, он должен успевать —
   проверить на устройстве.
2. **`minSilenceMs` 300 лучше дефолтных 450 на всём наборе:** медиана задержки
   −0,14 с, p90 −41 %, WER и spkErr без изменений, группа из 3 голосов
   разделяется верно. Но синтетика говорит с чистыми паузами; на живой речи с
   запинками 300 мс может рвать фразы. **Перед сменой дефолта — проверить на
   реальных записях.**
3. **Длинный хвост задержки (до 11 с) — из-за реплик встык.** Когда собеседники
   говорят без пауз, VAD держит один чанк на 10–15 с с 3–5 репликами; разрез по
   смене спикера делается после закрытия чанка, и первая реплика ждёт конца всего
   чанка. Пример: `syn26_simult2`, реплика 10,2–15,6 с пришла через 11,2 с.
4. **`maxSpeechMs` этот хвост не лечит** (серия C: максимум 11 → 10 с). Silero в
   sherpa-onnx 1.13.0 не закрывает сегмент на лимите, а `splitLongVadSegment`
   режет уже закрытый сегмент — задержку это не сокращает. Это защита от
   гигантских кусков, не рычаг для задержки.
5. **Что может срезать хвост:** (а) резать по смене спикера, пока чанк ещё
   открыт, и отдавать готовые куски сразу; (б) двойной проход — черновик текста
   виден сразу, финал приходит как сейчас.
6. **Атрибуция спикеров в группах — главная слабость по качеству.** Лог
   (`setprop log.tag.Speech DEBUG`) на `syn25_group3` при дефолтах: новые голоса
   получают косинус 0,28–0,31 с кластером 0 (ниже порога 0,45), но кандидат в
   новый кластер не набирает 2,5 с речи и реплики уходят спикеру 0.

## Ошибка: batch падает с SIGSEGV на монологе

`SherpaTranscriber` (batch, авторежим) роняет процесс нативным SIGSEGV внутри
`OfflineSpeakerDiarization.processWithCallback` (sherpa-onnx 1.13.0) на
`syn45_mono1` — 36,5 с, один спикер, без шума. Kotlin это не перехватит:
падает весь процесс. Streaming этот код не использует.

| `autoClusterThreshold` | Результат |
|---|---|
| 0,70 / 0,75 | работает, 1 спикер |
| **0,80 (дефолт)** / 0,85 / 0,90 | **SIGSEGV**, воспроизводится стабильно |
| `expectedSpeakers` = 1 или 2 | работает |

Адрес падения — в зарезервированной недоступной области кучи, не на стеке:
это выход за границу буфера в нативном коде, а не переполнение стека. Похоже,
ломается кластеризация, когда все фрагменты сливаются в один кластер; готового
исправления в sherpa-onnx не найдено. Важно для приложения: batch подключается
в `:app`, и монолог на демо уронит его. Tombstone в git не хранится; падение
воспроизводится командой ниже.

Повтор:

```bash
bash speech/scripts/benchmark.sh --wav speech/eval/golden/syn45_mono1.wav \
    --mode batch --runs 1 --no-build    # Instrumentation failed: Process crashed
```

## Ограничения

- Только эмулятор x86_64; телефона с adb не было.
- Один прогон на конфигурацию, разброс не оценён.
- Синтетическая TTS-речь с чистыми паузами; живую речь надо проверить отдельно.
- WER завышен расхождением в записи чисел; для сравнения конфигураций это не
  мешает, абсолютное значение — с оговоркой.
