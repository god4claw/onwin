# Расшифровка файлов: batch против VAD-пайплайна

Дата: 2026-11-06. Ветка `feat/speech-vad-transcriber`. Эмулятор API 36 x86_64,
4 ядра, один прогон на файл.

Жюри проверяет приложение загрузкой трёх аудиофайлов: оценивается расшифровка
готовой записи, а не живой стриминг. Критерии: точность транскрибации — 40,
диаризации — 35, временных меток — 10, скорость — 10.

## Что сравнивали

| | `SherpaTranscriber` (batch) | `SherpaVadTranscriber` (новый) |
|---|---|---|
| Сегментация | pyannote segmentation | АРУ → Silero VAD, разрез по смене спикера |
| Спикеры | CAM++ + FastClustering (sherpa-onnx) | CAM++ + перекластеризация по всей записи |
| ASR | GigaAM-v3 e2e CTC по сегментам | то же, по репликам VAD |

`SherpaVadTranscriber` — пайплайн streaming, которому файл подаётся целиком
без пауз; наружу — обычный `Transcriber`, приложению хватает замены одной
строки в `AppContainer`.

## Результат

8 файлов golden set + 18 файлов отложенной выборки (синтетика
`ivkond/synthetic-speech-diarization-ru`: 1–4 голоса, шумы, одновременная речь).

| | batch | VAD, авто | VAD, число спикеров задано |
|---|---:|---:|---:|
| **WER**, golden / отложенная | 18,0 / 19,7 % | **16,6 / 16,2 %** | 16,6 / 16,2 % |
| **spkErr**, среднее, golden / отложенная | 18,7 / 13,1 % | **5,9** / 12,7 % | 7,9 / **10,6 %** |
| Число спикеров верно | 4/8, 14/18 | 8/8, 13/18 | **8/8, 18/18** |
| Метки времени: медиана ошибки начала / конца | 0,93 / 0,86–0,94 с | 0,90–0,99 / **0,62–0,74 с** | то же |
| RTF (меньше — быстрее) | 0,17 | **0,064–0,076** | 0,064–0,070 |
| Падения | **1** (монолог, SIGSEGV) | 0 | 0 |

Вывод: для файлов `SherpaVadTranscriber` лучше или не хуже по всем четырём
критериям и не падает. Подсказка числа спикеров (`expectedSpeakers`) даёт
верное число во всех 26 файлах, но на golden set ошибка атрибуции чуть растёт:
принудительное число кластеров сливает и неоднозначные пары.

Оговорки: только синтетика. На реальной 18-минутной записи (Pear Chats, замеры
до АРУ и перекластеризации) batch был чуть точнее по диаризации — реальную
запись с эталоном нужно прогнать ещё раз.

## Куда уходят ошибки (VAD, авто, 26 файлов)

- **DER на синтетике почти весь — «пропущенная речь» (31–42 %), но слов при
  этом почти не теряется.** Эталонные реплики — сплошные интервалы с паузами
  между фразами внутри, наши сегменты эти паузы вырезают. Абсолютный DER на
  этих данных не показателен; смотрим spkErr. Метки времени — тоже только для
  сравнения.
- **Настоящие потери речи — в шуме:** `hold39_white2` (белый шум) — удалено 13
  слов из 40; заметные удаления ещё на 4 файлах. Это VAD.
- **WER 16,3 % = 259 ошибок:** замены 123, удаления 55, вставки 38, числа 43
  (≈ 17 % ошибок: «десять» в эталоне — «10» у GigaAM e2e). Остальное — имена
  собственные, окончания, слова второго голоса при одновременной речи.

## Что изменилось в коде

- `SherpaVadTranscriber` (`speech/impl`), README рекомендует его для файлов.
- `SpeakerReclusterer.relabel(records, expectedSpeakers)`: при известном числе
  участников сливает до него, без порога.
- Бенчмарк: `--mode vad` — файл через `SherpaVadTranscriber`, как в приложении.
- `stream_report.py`: колонки ошибки меток времени (`tsStart`, `tsEnd`), режим
  `vad`, число верных спикеров в итоговой строке.
- `make_golden.py`: границы реплик сужены до речи (в чистых файлах паузы —
  цифровой ноль); шумные файлы остаются со «слотами».

## Как воспроизвести

```bash
bash speech/eval/run_golden.sh bench-results/vad --mode vad --runs 1
bash speech/eval/run_golden.sh bench-results/batch --no-build --mode batch --runs 1
GOLDEN_DIR=speech/eval/holdout bash speech/eval/run_golden.sh bench-results/vad-holdout \
    --no-build --mode vad --runs 1
```

Сырые JSON прогонов в git не хранятся (локально — `bench-results/`): повторить
можно бенчмарком `../../speech/scripts/benchmark.sh`.
