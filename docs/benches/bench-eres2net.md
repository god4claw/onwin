# ERes2Net вместо CAM++ для спикеров

Дата: 2026-11-07. Ветка `feat/speech-eres2net` (поверх `feat/speech-word-speakers`).
Расшифровка файлов через `SherpaVadTranscriber` (`--mode vad`), эмулятор API 36
x86_64, один прогон на файл.

## Зачем

Синтетика (TTS-голоса) не показывала главную слабость CAM++: модель
`3dspeaker_speech_campplus_sv_zh-cn_16k-common` обучена на китайской речи и
плохо различает два женских голоса. На живых голосах это видно сразу.

Новый набор с живыми голосами — `../../speech/eval/make_dialogs.py`: реплики трёх
актёров корпуса [Dialogs](https://huggingface.co/datasets/langswap/dialogs-ru-emotional-conversations)
(OpenRAIL; Маша Ж, Света Ж, Дима М) склеены в разговоры по 24 реплики с
естественными паузами, условия clean / noise (розовый шум ~15 дБ) / far (второй
голос −12 дБ). Пара Ж/Ж — половина набора.

- `dialogs` (12) — на нём подбирались порог и доля;
- `dialogs2` (12, `--set2`) — другие части корпуса, только для проверки.

## Итог

Ошибка спикеров (spkErr) — доля времени с неверным спикером там, где и в
эталоне, и в ответе говорит один; кластеры сопоставляются с эталонными
жадно один-к-одному, лишний кластер — ошибка. F/F — пара Маша/Света.
WER здесь — с прежней нарезкой и прежней нормализацией; после исправлений
из [`bench-asr-edges.md`](bench-asr-edges.md) у ERes2Net 3,9 / 3,7 % на dialogs / dialogs2.

| Набор | Модель | WER | spkErr | спикеров верно | F/F |
|---|---|---:|---:|---:|---:|
| dialogs | CAM++ | 7,6 % | 24,3 % | 7/12 | 45,9 % |
| | **ERes2Net** | 8,5 % | **5,4 %** | **11/12** | **8,9 %** |
| dialogs2 (проверка) | CAM++ | 5,6 % | 23,2 % | 5/12 | 44,3 % |
| | **ERes2Net** | 6,7 % | **4,5 %** | **12/12** | **7,9 %** |
| синтетика, 26 файлов | CAM++ | 15,9 % | 7,9 % | 21/26 | |
| | ERes2Net | 16,5 % | 13,5 % | 15/26 | |
| val2 (19) | CAM++ | 20,5 % | 7,6 % | 15/19 | |
| | ERes2Net | 19,8 % | 13,2 % | 12/19 | |

Модель: `3dspeaker_speech_eres2net_sv_en_voxceleb_16k.onnx` (VoxCeleb),
26 МБ, теперь `SpeechConfig.embeddingModel` по умолчанию. CAM++ остаётся в
assets как запасной вариант (`EmbeddingModel.CAMPLUS`).

- **На живых голосах ошибка спикеров падает в 4–5 раз**, пара Ж/Ж из
  безнадёжной (≈ 45 %, два голоса сливаются в одного) становится рабочей.
- **На синтетике ERes2Net хуже:** TTS-голоса в шуме дробятся на лишние
  кластеры (до отсечения малых — 4 → 8, 3 → 6, 2 → 5 спикеров). Живые голоса
  ближе к тому, что будет у жюри, поэтому выбран ERes2Net.
- WER на живых голосах вырос из-за разрезов: детектор смены говорящего с
  ERes2Net ставит больше точек при том же пороге. Это исправлено отдельно —
  распознаванием чанка целиком ([`bench-asr-edges.md`](bench-asr-edges.md)).

## Подбор (симуляция перекластеризации по сохранённым embedding-ам)

- Порог перекластеризации `speakerReclusterThreshold` 0,60 → **0,65**.
- Новое `speakerMinShare = 0.15`: кластер с долей речи меньше 15 % вливается в
  самый похожий центроид. Без него ERes2Net почти в каждом шумном файле
  заводит лишних спикеров:

| minShare | dialogs + dialogs2: spkErr / верно | синтетика 26: spkErr / верно | val2: spkErr / верно |
|---:|---:|---:|---:|
| 0 | 12,1 % / 7 из 24 | 16,1 % / 12 из 26 | 15,8 % / 8 из 19 |
| 0,10 | 5,4 % / 22 | 14,6 % / 13 | 13,8 % / 9 |
| **0,15** | **5,0 % / 23** | **13,3 % / 15** | **13,1 % / 12** |

Цена: в группе с тихим участником, который говорит меньше 15 % времени, он
вливается в соседа (v58: 4 → 2 спикера). Для 2–3 говорящих это редкость.

## Скорость и память

ERes2Net в 2,8 раза тяжелее CAM++: на хосте 85 мс против 30 мс на окно 1,6 с
(1 поток). Окна поиска смены говорящего идут каждые 0,8 с, поэтому RTF растёт;
точный замер на устройстве — в [`bench-asr-edges.md`](bench-asr-edges.md).
PSS процесса бенчмарка ~570 МБ.

## Веса

ERes2Net нет в архиве `speech-models-v1`: файл скачивается отдельно по
публичной ссылке релиза sherpa-onnx (команды — в `../../INSTALL.md`),
SHA-256 `c59158379255ad66e161679cca6af8d52d51e389e3224ab7d7a7baae295c2db5`.
`verifyBundledModels` и `load()` без него падают.

## Что изменилось в коде

- `EmbeddingModel.ERES2NET`, `SpeechConfig.embeddingModel = ERES2NET`,
  `speakerReclusterThreshold = 0.65f`, `speakerMinShare = 0.15f`.
- `SpeakerReclusterer`: отсечение малых кластеров (`minSpeakerShare`).
- `ModelRegistry` / `BundledModels` / `models.sha256`: шестой файл.
- Бенчмарк: `--embedding-model`, `--recluster-threshold`, `--dump-embeddings`
  (embedding-и реплик в JSON — для подбора без устройства).
- Оценка: `../../speech/eval/make_dialogs.py`.
