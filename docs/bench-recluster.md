# Финальная перекластеризация спикеров в псевдостриминге

Дата: 2026-11-06. Ветка `feat/speech-recluster` (поверх `feat/speech-agc`).
Стенд — [`bench-golden-baseline.md`](bench-golden-baseline.md), АРУ включена в
обоих сравниваемых вариантах. Метрика атрибуции — **spkErr** (доля времени,
отданного не тому спикеру, там, где и в эталоне, и в гипотезе один спикер), см.
[`speech/eval/README.md`](../speech/eval/README.md).

## Проблема

Онлайн-кластеризатор решает по одной реплике и только по прошлому. Чтобы не
плодить «спикеров» из шума, он ждёт 2,5 с речи нового голоса и до этого отдаёт
реплики ближайшему кластеру; финальный pruning выкидывал кластеры короче 3 с.
На живой записи это сливало собеседника, который отвечал коротко, с основным
(в логе `speakers=2->1`). На отложенной выборке текущий код нашёл одного
спикера вместо двух в **8 из 16** диалогов.

## Что сделано

`SpeakerReclusterer` (`speech/impl`): в `Done` все реплики сессии с их
embedding-ами кластеризуются заново.

1. Агломеративная кластеризация по центроидам: кластер — сумма нормированных
   embedding-ов с весом √длительности (не больше √8 с), сходство — косинус
   сумм; сливаем самую похожую пару, пока сходство ≥ 0,60
   (`SpeechConfig.speakerReclusterThreshold`).
2. Кластер короче 2,5 с остаётся отдельным спикером, только если в нём ≥ 2
   реплик и он ни на кого не похож (косинус < 0,40); иначе вливается в самый
   похожий — одиночная вспышка шума не становится спикером.
3. Реплики без embedding (< 0,5 с) — метка ближайшей по времени.
4. Длинные сессии (> 600 реплик) сначала склеивают соседние реплики с одной
   онлайн-меткой: 2000 реплик (~1,5 ч) — меньше секунды в JVM-тесте.

`Utterance` по-прежнему приходит с онлайн-меткой; финальные номера — в `Done`.
Текст не меняется, только метки.

## Как подбирали

1. Бенчмарк научился писать embedding каждой реплики (`--dump-embeddings`).
2. Алгоритм и сетка параметров — на хосте
   ([`speech/eval/recluster_sim.py`](../speech/eval/recluster_sim.py)), секунды на
   итерацию вместо пересборки APK.
3. Параметры подобраны на золотом наборе (8 синтетических разговоров + 3 живые
   записи) и **проверены без подстройки** на отложенной выборке — 18 других
   разговоров того же датасета (`make_golden.py --holdout`).
4. Kotlin-версия на эмуляторе дала по каждому файлу те же цифры, что прототип.

Разделимость embedding-ов CAM++ на золотом наборе: косинус пар реплик одного
спикера — медиана 0,62 (p10 0,45), разных — 0,31 (p90 0,51).

## Результат

### Отложенная выборка (параметры её не видели)

| | Онлайн + pruning | Перекластеризация |
|---|---:|---:|
| spkErr, среднее | 25,1 % | **12,7 %** |
| spkErr, медиана | 23,2 % | **1,9 %** |
| Число спикеров верно | 9 из 18 | **13 из 18** |

Чувствительность к порогу на отложенной выборке: 0,50–0,55 — среднее 16,6 %,
13 из 18; 0,65 — 8,6 %, но число спикеров верно в 12 из 18. 0,60 — компромисс.

### Золотой набор

| файл | до | после |
|---|---:|---:|
| syn00_dialog2 | 5,1 % | 5,1 % |
| syn17_noise_white | 10,5 % | 6,7 % |
| syn25_group3 | 30,8 % | **2,8 %** |
| syn26_simult2 | 25,1 % | 19,7 % |
| syn31_interview2 | 0,0 % | 0,0 % |
| syn35_group4 | 13,6 % | 8,8 % |
| syn45_mono1 | 0,0 % | 0,0 % |
| syn62_noise_cafe | 13,2 % | **4,0 %** |

Число спикеров верно во всех 8 файлах до и после; WER не меняется.

### Что не решено

- **Реплики двух людей в одном VAD-чанке** (ответ без паузы после собеседника):
  чанк получает одну метку. На живой записи разговора spkErr остался 18 % —
  именно из-за этого. Нужна привязка спикера к словам (этап B: ASR целиком по
  чанку, таймкоды токенов, смена спикера по коротким окнам).
- Отложенная выборка: два диалога с похожими голосами сливаются (2 → 1),
  группа из 4 голосов в шуме толпы — 2 спикера, один диалог с гулом — 3.
- Метки в `Utterance` по ходу записи по-прежнему онлайн; обновление на лету —
  отдельное событие API (этап C).

## Как воспроизвести

```bash
# embedding-и (темп подачи не нужен — нарезка от него не зависит)
bash speech/eval/run_golden.sh bench-results/emb --mode streaming --runs 1 --dump-embeddings
GOLDEN_DIR=speech/eval/holdout bash speech/eval/run_golden.sh bench-results/emb-holdout \
    --no-build --mode streaming --runs 1 --dump-embeddings
# подбор и проверка на хосте
python speech/eval/recluster_sim.py bench-results/emb --refs speech/eval/golden --grid
python speech/eval/recluster_sim.py bench-results/emb-holdout --refs speech/eval/holdout
```

Сырые JSON прогонов в git не хранятся (локально — `bench-results/`): повторить
можно бенчмарком `speech/scripts/benchmark.sh`.
