# GigaAM-v3 e2e RNN-T вместо e2e CTC

## Итог

Модель ASR по умолчанию — GigaAM-v3 **e2e RNN-T** из релиза sherpa-onnx
`asr-models` (`sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16`).
Вывод тот же, что у прежней e2e CTC: пунктуация, регистр, числа цифрами.

На эмуляторе в режиме файла (`SherpaVadTranscriber`), попарно по 69 файлам:

| Набор | WER CTC → RNN-T | Ошибка атрибуции, медиана | Спикеров верно | Начало реплики, медиана | PSS |
|---|---|---|---|---|---|
| живые диалоги (24) | 3,81 → **3,70 %** | 2,4 → 2,3 % | 23 → 23 | 0,18 → 0,14 с | 594 → 526 МБ |
| синтетика (26) | 16,18 → **15,11 %** | 0,6 → 0,7 % | 17 → 17 | без изменений | 492 → 410 МБ |
| val2 (19) | 19,47 → **17,83 %** | 5,9 → 7,2 % | 11 → 10 | без изменений | 496 → 408 МБ |

- WER лучше в 40 файлах, хуже в 16, без изменений в 13. Больше всего выигрыш на
  монологе (15,7 → 2,0 %) и групповых разговорах с наложением речи (−7…−9 п.п.).
- Диаризация в целом не меняется. На трудных групповых файлах кластеризация
  нестабильна в обе стороны (52,8 → 13,7 % и 32 → 66 % на соседних файлах).
- RTF в одной сессии 0,202 → 0,236: примерно на 17 % медленнее.
- Файлы модели — 232 МБ против 305 МБ; CTC стала необязательной, без неё APK меньше.

## Пять версий GigaAM-v3 на хосте

Одинаковая VAD-нарезка для всех (Silero 0,35 / 450 мс / 250 мс, разрез длинных
кусков в тишине, без АРУ), greedy, 3 потока, ~2 ч аудио, 70 файлов.

| Модель | живые (24) | синтетика (45) | пропуски слов | RTF |
|---|---|---|---|---|
| e2e CTC, наш экспорт (свёртки fp32) | 3,98 % | 19,42 % | 308 | 0,092 |
| e2e CTC, k2-fsa (всё int8) | 3,96 % | 19,79 % | 332 | 0,113 |
| **e2e RNN-T, k2-fsa** | **3,92 %** | **17,76 %** | 309 | 0,109 |
| CTC без пунктуации | 3,83 % | 20,52 % | 458 | 0,103 |
| RNN-T без пунктуации | 3,38 % | 21,30 % | 558 | 0,105 |

- RNN-T без пунктуации лучшая на живых голосах, но на одновременной речи и в шуме
  выбрасывает целые фразы (до 40 слов подряд), пропусков почти вдвое больше.
  Латиницу не пишет вовсе. Не взята.
- Наш экспорт CTC с fp32-свёртками точности не добавляет, а весит на 90 МиБ больше.
- Хостовый WER e2e CTC на живых (3,98 %) совпадает с эмулятором (3,7–3,9 %).

## Числа и латиница

Числа сравнивались по значению («двадцать пять» = «25» = «25-го»), 150 чисел в эталонах:

| | e2e CTC | e2e RNN-T |
|---|---|---|
| верно по значению | 127 (85 %) | **140 (93 %)** |
| другое значение | 2 | 0 |
| словом или искажено («т1ринадцатое», «15тд») | 11 | 5 |
| пропущено | 10 | 5 |

Из «лишних» чисел RNN-T 8 — запись времени «10:00 утра» при эталоне «десять
утра», остальные — слова второго голоса при наложении речи. Если числа
сравнивать по значению, WER на всех наборах 7,29 → 6,64 %: формат записи чисел —
около 9 % ошибок, вопрос к организаторам.

Латинские слова в эталонах (бренды, 71): верно латиницей 32 % у CTC и 38 % у
RNN-T, остальное — в основном кириллицей («твиттер», «сири»). Смесь алфавитов в
одном слове («fайсбоок») у CTC 3 раза, у RNN-T ни разу. Чистый английский обе
модели пишут латиницей «на слух» с ошибками примерно в двух словах из трёх.

## Шумоподавитель — не взят

GTCRN и DPDFNet (baseline/2) из sherpa-onnx на 43 шумных и «дальних» файлах,
RNN-T: очищенный сигнал в ASR хуже на 0,5–0,9 п.п.; только для VAD — 7,04 → 6,93 %
(шум 8,60 → 8,01 %, дальний микрофон 5,47 → 5,86 %), разброс по файлам ±12 ошибок
без связи с уровнем фона. Атрибуция спикеров на шумных файлах не хуже, чем на
чистых; слабое место — группы и наложение речи (медиана 11–12 %).

## Повтор

Сырые JSON прогонов в git не хранятся (локально — `bench-results/`): повторить
можно бенчмарком `speech/scripts/benchmark.sh`:

```bash
for f in speech/eval/dialogs/*.wav; do
  bash speech/scripts/benchmark.sh --wav "$f" --mode vad --runs 1 --asr-model e2e_rnnt --out bench-results/rnnt/dialogs --no-build
done
python3 speech/eval/stream_report.py bench-results/rnnt/dialogs --refs speech/eval/dialogs
```

`--asr-model e2e_ctc` — прежняя модель (её файлы нужно положить в assets).
