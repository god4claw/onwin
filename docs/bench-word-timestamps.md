# Метки времени слов: спикеры по словам и границы реплик

Дата: 2026-11-06. Ветка `feat/speech-word-speakers` (поверх
`feat/speech-vad-noise`). Расшифровка файлов через `SherpaVadTranscriber`
(`--mode vad`), эмулятор API 36 x86_64, один прогон на файл.

Наборы: golden (8) + отложенная выборка (18) — 26 файлов для сравнения
вариантов; **val2** (19) — только для финальной проверки, на ней ничего не
подбиралось.

## Что хотели

1. Чтобы короткий ответ, сказанный без паузы после собеседника, получал своего
   спикера, а не метку всего VAD-чанка.
2. Чтобы разрез по смене говорящего не ломал слова на стыке («так» → «ак»).
3. Чтобы границы реплик шли по словам, а не по краям VAD-чанка.

GigaAM через sherpa-onnx отдаёт метки времени токенов (шаг 40 мс, без
длительностей); слова собираются по `▁`, пунктуация CTC приходит с
запозданием (на замере «?» — через 2 с после слова), поэтому конец слова
считается по последнему буквенному токену + 0,25 с, начало — на 0,1 с раньше
метки первого токена.

## Что пробовали (26 файлов)

| Вариант | WER | spkErr | спикеров верно | RTF |
|---|---:|---:|---:|---:|
| База: разрез аудио по тихому кадру, границы — края кусков | **15,9 %** | 9,1 % | 19/26 | 0,073 |
| W1: ASR всего чанка, текст делится по словам, аудио не режется | 18,6 % | 7,1 % | 22/26 | 0,074 |
| H3: разрез в ближайшей паузе между словами, куски распознаются заново | 16,6 % | 7,3 % | 19/26 | 0,093 |
| H4: то же, самая тихая пауза между словами в пределах 1 с | 16,4 % | 7,3 % | 19/26 | 0,093 |
| **H6: разрез по тихому кадру (как в базе) + слова для границ, embedding по словам, склейка** | **15,9 %** | **6,5 %** | **21/26** | 0,081 |

- **W1 провалился на наложении голосов:** на файле с одновременной речью
  GigaAM, распознавая 20-секундный чанк целиком, выдал почти мусор (52
  удалённых слова вместо 1). Короткие куски с одним голосом он распознаёт
  лучше длинных.
- **Разрез в паузе между словами (H3, H4) отрезал концы фраз:** точка смены
  по embedding-ам известна лишь до ±0,8 с (шаг окон), и разрез уходил в паузу
  внутри фразы («из Урюпинска в Читу» → «из Урюпинска.» + «И…»). Разрез по
  тихому кадру попадает в паузу между репликами.
- Более мелкая сетка поиска смены говорящего (окно 1,2 с, шаг 0,4 с) хуже по
  всем метрикам.
- **Выигрыш по спикерам дали не разрезы, а:** embedding по участку со словами
  (без пауз по краям), границы реплик по словам и склейка соседних кусков
  одного чанка с одним финальным спикером (ложный разрез).

по-прежнему распознан раздельно.

## Метки времени — без калибровки

На синтетике наши реплики начинаются позже эталона (медиана +0,5 с в чистых
файлах, +0,9 с в шумных) и заканчиваются раньше (−0,6…−0,8 с) — и в базе, и в
H6. Эталон даже после обрезки по ненулевым сэмплам захватывает дыхание и фон
TTS вокруг фразы, поэтому подгонять границы под него не стали: H6 даёт
границы ближе к реальной речи. Как размечены метки времени у жюри, неизвестно —
вопрос к организаторам; запас по краям — две константы
(`StreamingChunkProcessor.PRE_ROLL_SAMPLES`, `assembleWords(endPadSamples)`).

## Не сделано

- Склеенные куски не распознаются заново: текст на месте ложного разреза
  остаётся испорченным. Склеек немного (20 на ~480 реплик), выигрыш был бы
  небольшим.

## Что изменилось в коде

- `AsrRunner.transcribeWords`, `assembleWords` — слова с границами из токенов.
- `StreamingChunkProcessor.process`: точки смены → разрез по тихому кадру
  (`chooseCuts`) → ASR кусков со словами → реплика по словам, embedding по
  словам; `SegmentRecord.chunkIndex`.
- `SpeakerChangeSplitter.findBoundaries` вместо разреза аудио;
  `SpeechConfig.speakerChangeHopMs`.
- В `Done`: `mergeSameSpeakerNeighbors` после перекластеризации.
- Бенчмарк: `--speaker-change-window-ms/-hop-ms/-min-ms`.

Сырые JSON прогонов в git не хранятся (локально — `bench-results/`): повторить
можно бенчмарком `speech/scripts/benchmark.sh`.
