# Goal

> Установка, веса и сборка — [`INSTALL.md`](INSTALL.md). Устройство движка — [`speech/README.md`](speech/README.md).

Разработать Android-приложение, которое локально преобразует аудиозаписи разговоров в текст, автоматически определяя говорящих и разделяя их реплики. Приложение должно формировать структурированную расшифровку диалога с указанием участников и временных меток.

# Progress

## :app
Модуль использует офлайн-движок `SherpaVadTranscriber` из `:speech`. Для распознавания в APK нужны веса из [инструкции по установке](INSTALL.md#2-веса).

### Структура модуля

- `ui` содержит Compose-экраны, ViewModel, навигацию и foreground-сервис с уведомлениями.
- `domain` содержит модели сессий, контракты хранилищ и очередь записи и обработки. Этот слой работает без Android и Room.
- `data` содержит Room, DataStore, захват и конвертацию аудио. Репозиторий преобразует строки Room в модели `domain`.

Hilt создаёт общие для приложения Room, репозиторий, очередь, foreground-координатор и движок. Инъекция контроллера в `Application` запускает восстановление незавершённых сессий при старте процесса.

Основной шрифт интерфейса — Golos Text. Playfair Display используется в заголовках экранов списка и приветствия, в заголовках нижних панелей, а также в названиях и статусах записей в списке и на экране записи. Оба шрифта встроены в приложение.

`Готово:`

- Полноэкранное приветствие при первом запуске. «Начать» сохраняет флаг локально и открывает записи. При следующем запуске сразу открываются записи. Очистка данных или переустановка снова включает приветствие.
- После «Начать» содержимое списка поднимается снизу, а содержимое приветствия уходит вверх. При открытии записи содержимое списка уходит влево, а содержимое записи въезжает справа. При возврате движение зеркальное. Фон и нижняя панель остаются на месте. Высота и содержимое панели меняются плавно, а переключатель расшифровки закреплён над панелью на экране списка.
- Экран «Записи» показывает превью Room и раскрывает прокручиваемый список. Карандаш в карточке открывает диалог с текущим названием, корзина — подтверждение удаления выбранной записи. Клавиатура появляется по касанию поля названия. Микрофон запускает запись и открывает её экран.
- «Импортировать с устройства» открывает системный выбор одного аудиофайла. Поддерживается MP3 и другие аудиоформаты, для которых на устройстве есть декодер. Импортированный файл конвертируется в WAV и передаётся в очередь расшифровки.
- Экран записи показывает таймер и позволяет остановить запись или отменить её с подтверждением. При возврате к списку запись продолжается, а нижняя панель предлагает остановить запись или импортировать аудио. Движок выдаёт реплики по мере распознавания и уточняет спикеров в конце. Во время обработки нижняя панель показывает индикатор и позволяет отменить расшифровку с сохранением аудио.
- После обработки на экране записи можно воспроизвести сохранённый WAV, поставить его на паузу и перемотать по шкале.
- «Экспорт в документ» под готовой расшифровкой открывает выбор формата (JSON, PDF, Markdown или TXT), затем системный выбор папки и имени файла. PDF, Markdown и TXT содержат название записи, реплики, интервалы и имена спикеров. JSON сохраняет массив `transcript` с текстом, стабильными идентификаторами спикеров и временем в миллисекундах.
- В готовой расшифровке нажатие на имя спикера открывает диалог переименования. Имя сохраняется для всех реплик этого спикера в записи. «Сбросить имя» возвращает подпись «Спикер N».
- Compose UI: список записей и экран записи, статусы, прогресс по этапам, ошибки, отмена/повтор/удаление.
- Импорт через OpenDocument. Запрос уведомлений на Android 13+ открывается только по кнопке «Включить уведомления» на экране активной записи или обработки.
- Room: сессии, сегменты, имена спикеров, экспорт схемы; восстановление INTERRUPTED после смерти процесса, чистка осиротевших WAV.
- Очередь: один воркер, load() на пачку, release() в конце, foreground-сервис (dataSync|mediaProcessing), wakelock, сегменты пишутся в БД по мере готовности.
- Готовая расшифровка доступна сразу. При наличии локальной LLM автоматически появляются «Кратко» и предложенные имена спикеров. Кнопка «Провести коррекцию» в том же блоке запускает правку реплик и показывает индикатор до завершения. Для англоязычных расшифровок правка недоступна.
- Конвертация: AudioConverter, PcmPipeline, StreamingResampler, RiffWavReader, канонический WAV; JVM- и instrumented-тесты, включая длинный вход.

### Запись с микрофона

- Нажмите «Записать» и разрешите доступ к микрофону. Запись можно начать во время обработки другого файла, а импорт доступен и во время записи, и во время обработки.
- Переключатель «Расшифровка во время записи» расположен справа над нижней панелью и доступен при раскрытом списке. Он включён по умолчанию. В этом режиме реплики появляются по мере захвата после загрузки моделей. Выключите переключатель перед началом записи, чтобы распознавание началось после «Стоп». Оба режима работают офлайн.
- Запись продолжается при выключенном экране и в фоне. Если уведомления разрешены, в шторке есть таймер и кнопка «Завершить и сохранить». Для отмены записи откройте её экран нажатием на уведомление.
- Когда расшифровка заканчивается в фоне, появляется тихое уведомление о готовности. Несколько результатов объединяются в одну карточку, которая открывает последнюю готовую расшифровку.
- Запись занимает место в очереди при старте, импорт — при выборе файла. «Остановить» сохраняет WAV 16 кГц / моно / PCM16. Если обработчик ещё занят предыдущим файлом, микрофон продолжает запись. Когда наступит её очередь, живой режим прочитает и уже записанный звук, и новые данные. Отложенный режим ждёт сохранения WAV.
- При импорте в занятую очередь список остаётся открытым. Если очередь была свободна, откроется карточка нового файла.
- «Отменить» во время захвата удаляет незавершённое аудио. Отмена последующей расшифровки сохраняет исходный WAV для повтора.
- При первом открытии готовой расшифровки с доступным аудио две подсказки показывают, как перейти к началу реплики и переименовать спикера. После выхода с экрана показ продолжится с незавершённого шага. После второго шага подсказки больше не появляются.
- При потере микрофона, отзыве разрешения или принудительном завершении процесса незавершённая запись не восстанавливается. Начните новую запись. Готовые WAV сохраняются.
- Захват использует AudioRecord и WavWriter. Foreground-сервис использует тип microphone с API 30 и тип mediaProcessing (API 35+) или dataSync (API 29–34) для обработки. При одновременной записи и обработке оба типа действуют вместе.

Проверки: `.\gradlew.bat :app:assembleDebug :app:lintDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest`.
На подключённом arm64-устройстве: `.\gradlew.bat :app:connectedDebugAndroidTest`.
Для проверки распознавания тестовой речи положите короткий WAV или MP3 в `app/src/androidTest/assets` и передайте его имя через `-Pandroid.testInstrumentationRunnerArguments.speechSample=example.mp3`. Тесты проверят появление реплик до «Стоп» и импорт с экспортом JSON.
Ручная проверка на телефоне: слышимая речь в WAV, разрешение и запрет уведомлений, экран блокировки, сохранение записи и отмена обработки из шторки, уведомление о готовности в фоне, конкурирующий захват микрофона, смерть процесса, работа без сети.

## :speech
Движок готов; диаризация проверена на двух голосах

`Готово:`

- Batch-пайплайн: pyannote segmentation + CAM++ + FastClustering → ASR GigaAM-v3 по сегментам, expectedSpeakers 1..20, AsrRunner режет куски >45 с по тихой границе.
- Диаризация проверена: `two_speaker_dialogue` (19,75 с, два голоса) — 2 спикера в batch и streaming, метки 0/1 по порядку. На 46,8-с фикстуре один TTS-голос, поэтому `spk=1` там — правильный ответ.
- Streaming: Silero VAD (окно 512), SpeechStarted, реплика закрывается по 450 мс тишины или 25 с, ASR в отдельной корутине, очередь на 8 чанков.
- Спикеры в streaming уже размечаются — CAM++ embedding + OnlineSpeakerClusterer по косинусу, спикер приходит в Utterance. В твоём описании v2 («спикеры пока не размечаются, speaker = 0») это уже устарело.
- Веса в assets, INTERNET в манифесте нет, сетевой загрузки в модуле нет.
- Тесты: JVM на VAD и кластеризацию, instrumented на bundled-модели, batch-диаризацию и стриминг; headless-бенчмарк.
- Документация: speech/README.md, BENCHMARK.md, AUDIO_DECODING.md.

`Не готово:`

- Цифр с arm64-телефона нет, только x86_64-эмулятор.
- WER/DER не измеряются: эталонных транскриптов нет, качество оценивается вручную.

## :llm
Рантайм локальной LLM для правки расшифровки; проверен на эмуляторе, выигрыш по WER не измерен

`Готово:`

- `OnnxGenAiGenerator` — `TextGenerator` поверх ONNX Runtime GenAI 0.19 (AAR в `llm/local-repo`) и ядра ORT 1.31.1: chat-шаблон, жадная генерация, проверка отмены на каждом токене.
- `LlmDialogueAnalyzer` — разбор диалога: чанкинг по 3 000 символов, голосование по именам спикеров (ничья — отказ, лучше без имени, чем с выдуманным), валидация резюме (эхо расшифровки, отсутствие букв нужного языка, короткий текст отбрасываются). Язык (RU/EN/MIXED) определяется по тексту и выбирает промпт.
- `ProtocolAnalyzer` там же: опциональный протокол по кнопке — участники детерминированно из сегментов и имён, summary/decisions/actions — текстовыми секциями (не JSON: ORT GenAI без GBNF), парсер и дедупликация в Kotlin. Для английского используется английский промпт, корректор на EN не запускается.
- `OnDeviceLlm` собирает все проходы на одной модели: `CompositeCorrector` (словарь + `LlmCorrector`), анализатор и протокол. Нет модели — `null`, приложение работает как раньше.
- Room v3 с миграциями 1→2 и 2→3: `session_notes`, `speaker_suggestions`, `session_protocols`; на экране записи — блок «Кратко», чипы «Спикер N — Имя» и кнопка «Составить протокол» с экспортом `.md`.
- Модель Qwen2.5-0.5B-Instruct (ONNX GenAI, int4) поставляется внутри debug и release APK. Для сборки положите `llm-model-v1.zip` в корень репозитория. Приложение распаковывает модель при первом использовании LLM. [Инструкция по сборке](INSTALL.md#2б-llm-модель).
- AAR объявляет `INTERNET` и телеметрию: разрешения и ContentProvider вырезаны из merged-манифеста, сборка это проверяет.
- Проверено на Pixel_8_API36: модель грузится, ответ на реплику ~10–15 с, гард не даёт переписать текст.

`Не готово:`

- Выигрыш по WER не измерен: нужен эталонный набор реплик (см. [`docs/llm-correction.md`](docs/llm-correction.md)).
- 0.5B-модель без примеров в промпте переписывает фразу по смыслу, с примерами — повторяет дословно и ничего не исправляет. Нужен подбор промпта или модели.
- Импорта модели в UI нет: только adb-скрипт.
- Анализ диалога и протокол проверены JVM-тестами с поддельным генератором; на устройстве с настоящей моделью проверены только генерация и корректор. Протокол на устройстве ещё не прогнан.

## Стек :speech v2
`это чисто on-device Android-библиотека на Kotlin без UI и сетевой зависимости в рантайме:`
- Платформа: Android Library (AGP 9.4.1, Kotlin 2.4.21), minSdk 29, compileSdk 37, Java 11.
- ASR/диаризация: нативный sherpa-onnx через JNI; AAR 1.13.0 (~38 МБ) лежит в локальном Maven-репозитории `local-repo` и подключается как `com.k2fsa.sherpa.onnx:sherpa-onnx:1.13.0`.
- Модели (все в `speech/src/main/assets`, читаются через `AssetManager`, без скачивания):
  - GigaAM-v3 e2e RNN-T (~232 МБ: encoder int8, decoder, joiner) — русское ASR с пунктуацией; прежняя e2e CTC (~305 МБ) — необязательный запасной вариант;
  - ERes2Net (~25 МБ) — speaker embeddings для диаризации; CAM++ (~27 МБ) — запасной;
  - pyannote segmentation int8 (~1.5 МБ) — диаризация;
  - Silero VAD (~0.6 МБ) — псевдостриминг;
  - словарь GigaAM RNN-T (~13 КБ);
  - Parakeet TDT 110M (~130 МБ) — английские фразы, язык определяется сам по выводу GigaAM.
- Офлайн: модуль не требует `INTERNET`; веса лежат в assets APK и проверяются по `models.sha256`. Сетевой загрузки в модуле нет.
- Упаковка: в `app/build.gradle.kts` нужен `androidResources { noCompress += listOf("onnx", "txt") }` — `noCompress` библиотеки не пробрасывается в APK приложения, а sherpa-onnx не умеет читать сжатые assets через `AAsset_getBuffer`.
- Псевдостриминг: `StreamingTranscriber` + `VadConfig`; `Flow<FloatArray>` 16 кГц / моно → VAD → offline-ASR по завершённым репликам. Текст и предварительные номера спикеров приходят по мере готовности реплик, окончательные номера — в `Done`.
- Асинхронность: Kotlin Coroutines + Flow (`TranscriptionEvent` в batch, `StreamingEvent` в streaming; `channelFlow`, `Mutex`, `Dispatchers.IO`).
- Аудио: `:speech` принимает только канонический WAV 16 кГц / моно / PCM16 (44-байтовый RIFF) в batch и `Flow<FloatArray>` в streaming. Декодирование mp3/m4a/ogg и разбор произвольных RIFF-чанков (`LIST`, `fact`, `WAVE_FORMAT_EXTENSIBLE`) — в `:app` (`AudioConverter` / `RiffWavReader`).
- Размер: debug-APK с весами и двумя ABI — ~433 МБ; первая загрузка моделей читает ~348 МБ из APK в память (на эмуляторе холодная загрузка ~25–31 сек, на телефоне быстрее).
- Тесты: JUnit4 + AndroidX Instrumentation/Espresso; JVM-тесты VAD-сегментатора, instrumented-тесты проверки bundled-моделей, VAD, batch-диаризации и псевдостриминга на TTS-диалоге.
